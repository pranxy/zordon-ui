# Contribution and compatibility policies

These documents turn the accepted architecture and build plan into repeatable contribution and
review decisions.

- [Contributor workflow](../../CONTRIBUTING.md): selecting, implementing, validating, documenting,
  and submitting work.
- [Public API review](api-review.md): the required review surface and approval checklist for
  consumer-facing contracts.
- [Deprecation and breaking changes](deprecation-policy.md): SemVer classification, migration, and
  removal lifecycle.
- [Component maturity](component-maturity.md): delivery-independent maturity labels and promotion
  gates.
- [Component documentation template](../templates/component-documentation-template.md): the
  component-local specification, examples, and evidence record used with the policies above.

The [build plan](../../DAISYUI_ANGULAR_BUILD_PLAN.md) remains the delivery source of truth. The
[architecture records](../architecture/README.md) remain authoritative for shared technical
decisions, and the [release guide](../guides/releasing.md) owns version preparation and publishing.
