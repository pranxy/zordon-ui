# Release pipeline research

## Question

What is the smallest safe 2026 release pipeline for `@pranxy/zordon-ui` that provides generated changelogs, preview/stable npm channels, provenance, and credential-free dry-run verification?

## Intended output

- Repository-owned version/changelog configuration.
- A deterministic package validation command.
- A manually gated provenance-enabled publish workflow.
- Maintainer documentation and executable validation evidence.

## Constraints and evidence bar

- Angular 21 workspace; Angular 21–22 consumer range.
- Package output is generated by ng-packagr under `dist/components`.
- No external npm or GitHub environment mutation is authorized.
- Publishing must never occur on ordinary push or pull-request CI.
- Behavior-sensitive claims require official npm, GitHub, and selected-tool documentation/source.

## Search angles

- npm trusted publishing, provenance, access, dist-tags, and dry-run behavior.
- GitHub Actions OIDC permissions, protected environments, and release triggers.
- Maintained changelog/version tooling with monorepo/prerelease support.
- Existing repository package metadata, semver ADR, CI, and branch/tag constraints.

## Sources and findings

- [npm trusted publishing](https://docs.npmjs.com/trusted-publishers/): GitHub-hosted runners,
  npm 11.5.1 or newer, `id-token: write`, exact repository/workflow/environment configuration,
  and public repository/package metadata are required. Trusted publishing avoids a long-lived npm
  token and supplies provenance; the workflow retains an explicit `--provenance` assertion.
- [npm publish](https://docs.npmjs.com/cli/v11/commands/npm-publish/) and
  [npm dist-tags](https://docs.npmjs.com/cli/v11/commands/npm-dist-tag/): package and publish dry
  runs are non-mutating, scoped packages require public access, and every release must pass an
  explicit dist-tag because the default is `latest`.
- [Changesets workflow](https://github.com/changesets/changesets/blob/main/docs/intro-to-using-changesets.md)
  and [prereleases](https://github.com/changesets/changesets/blob/main/docs/prereleases.md): stable
  Changesets v2 provides reviewable SemVer/changelog generation; prerelease mode belongs on a
  dedicated branch and uses its prerelease identifier as the npm channel.
- [GitHub environments](https://docs.github.com/en/actions/reference/workflows-and-actions/deployments-and-environments):
  a protected environment provides the human publish gate and tag deployment restriction.
- Repository audit: the authoritative manifest is `projects/components/package.json`, the default
  branch is `master`, ng-packagr builds `dist/components`, and CI incorrectly targeted `main`.

## Synthesis

- Changesets prepares version/changelog PRs but cannot publish.
- A GitHub Release is the only publish trigger. Its tag, prerelease flag, and built package version
  must agree before npm runs.
- Stable maps only to `latest`; `next`, `alpha`, `beta`, and `rc` map only to matching prerelease
  suffixes. The repository-owned validator rejects all other channels.
- The publish job uses a protected `npm` environment, read-only contents, OIDC, immutable action
  pins, and no npm token. Actual npm/GitHub account setup remains a documented maintainer action.
- If the package is new, npm requires a one-time 2FA or short-lived-token bootstrap publish before
  trusted publishing can be configured.
